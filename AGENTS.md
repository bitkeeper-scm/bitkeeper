# BitKeeper Agent Instructions

## Build, Test, and Packaging Commands

Building and testing in this repository is now primarily done with **Bazel**. The `Makefile` represents the legacy build method; in areas where Bazel configuration is still being updated or migrated, consult `Makefile` and `src/Makefile` as reference for how the original build and generation steps worked.

### Bazel Commands
- **Build core binary (`bk`)**: `bazel build //src:bk`
- **Build all targets**: `bazel build //...`
- **Build installation package**: `bazel build //src:install_image` (produces `bazel-bin/src/bitkeeper.tar.gz`)
- **Run all regression tests**: `bazel test //src/t:...`
- **Run a single test**: `bazel test //src/t:t_<testname>`
  - Dots in test filenames are converted to underscores (e.g., `src/t/t.basic` -> `bazel test //src/t:t_basic`)
- **Run a test with output**: `bazel test --test_output=errors //src/t:t_basic`

### Legacy Make (Reference / Migration)
- **Production build**: `make -C src p`
- **Debug build**: `make -C src g`
- **Installer image**: `make -C src image`
- **Run test harness directly**: `cd src/t && ./doit t.<testname>`

## High-Level Architecture

BitKeeper is a distributed revision control system implemented primarily in C with supporting shell, Perl, and Tcl/Tk components.

- **CLI Dispatcher (`src/bk.c`, `src/cmd.pl`)**:
  `bk` acts as a multi-call binary. Subcommand routing uses a perfect hash lookup (`cmd_lookup`) generated by `gperf` from `cmd.pl`. Adding or modifying CLI subcommands requires updating the `__DATA__` section of `src/cmd.pl`.
- **SCCS Engine (`src/sccs.h`, `src/sccs*.c`, `src/cset*.c`)**:
  The core versioning backend. Manages the revision graph, delta structures (`d1_t`, `delta`), weave formats, file encoding (BAM, gzip, uuencode), and SCCS history files (`SCCS/s.<file>`). Changesets represent repository commits via graph roots in `SCCS/s.ChangeSet`.
- **Repository Management & Locking (`src/proj.c`, `src/repo.c`, `src/lock.c`)**:
  Handles standalone and nested collection repositories (`ChangeSet` components), file namespaces, config files (`BitKeeper/etc/config`), identifier caching (`BitKeeper/log/x.id_cache`), and concurrency locking (`BitKeeper/readers/`, `BitKeeper/writer/`).
- **Remote & BKD Daemon Subsystem (`src/bkd*.c`, `src/remote.c`, `src/http.c`)**:
  Implements the BitKeeper network transport protocol (supporting `bk://`, SSH, HTTP, and local filesystem URLs). Remote daemon subcommands are prefixed with `bkd_` and marked `remote` in `src/cmd.pl`.
- **Portability & Support Libc (`src/libc/`)**:
  Provides system abstractions including `fslayer` (virtual filesystem intercept layer), memory-mapped database/hash helpers (`mdbm`, `hash_nokey`), custom stdio helpers, and platform portability code.
- **Third-Party Dependencies (`MODULE.bazel`, `third_party/`)**:
  External libraries (`zlib`, `lz4`, `pcre1`, `tomcrypt`, `tommath`) are resolved by Bazel via the Bazel Central Registry and upstream archive rules in `MODULE.bazel` / `//third_party/...`.

## Key Conventions & Code Patterns

### C Dialect & Style (`src/libc/style.h`, `src/sccs.h`)
- **Keywords & Control Flow**:
  - `private` is `#define private static`.
  - `unless (condition)` is preferred over `if (!(condition))`.
  - String comparisons use `streq(a, b)` and `strneq(a, b, n)` instead of `!strcmp()`.
  - Prefix/suffix matching uses `begins_with(str, prefix)` and `ends_with(str, suffix)`.
- **Types**:
  - Fixed-width integer typedefs: `u8`, `u16`, `u32`, `u64`, `i8`, `i16`, `i32`, `i64`.
  - Revision serial identifiers use `ser_t` (`u32`).
- **Allocation & Memory**:
  - Struct allocations use `new(Type)` which wraps `(Type *)calloc(1, sizeof(Type))`.
  - Strings stored within sccs structs live in the data heap (`sccs_addStr`, `sccs_addUniqStr`).
- **Process Exit**:
  - `exit(e)` is macro-aliased to `bk_exit(__FILE__, __LINE__, e)`. Avoid raw `_exit()`.

### Adding or Modifying Subcommands
- Each internal command function must have signature `int <name>_main(int ac, char **av)`.
- Register the command name in `src/cmd.pl` under `__DATA__`. Internal utilities start with an underscore (e.g., `_cleanpath` maps to `cleanpath_main`).
- Commands executed remotely over `bkd` must be implemented in `src/bkd_*.c` and flagged with `remote` in `cmd.pl`.

### Test Harness Conventions (`src/t/`)
- Regression tests are executable shell scripts named `t.<topic>` (or `i.<topic>` for interactive, `g.<topic>` for GUI tests).
- Every test script sources `setup` (`. ./setup` or executed via `doit`).
- Assertions in tests: use `fail` helper function when an invariant fails.
- Tests must use isolated working directories under `$TST_DIR` or relative to `$HERE`.
